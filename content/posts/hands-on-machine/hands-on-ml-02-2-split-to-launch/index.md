## 1. 문제 정의와 가정 검사 (2.2.1, 2.2.3) {#problem-framing}

### 1.1 어떤 종류의 문제인가

예제의 목표는 블록 그룹(이하 구역)의 인구, 중간 소득 같은 특성으로 그 구역의 중간 주택 가격을 맞히는 것이다. 정답 레이블이 있으므로 **지도 학습**, 맞힐 값이 연속값이므로 **회귀**이다. 특성을 여러 개 쓰므로 **다중 회귀**이고, 구역마다 값 하나를 예측하므로 **단변량 회귀**이다.

데이터가 계속 흘러 들어오지 않고 메모리에 다 들어가는 크기라 **배치 학습**으로 충분하다. 데이터가 아주 크면 여러 서버로 나눠 배치 학습을 하거나 온라인 학습을 쓴다.

캡스톤도 같은 분류에 속한다. 매물 조건 여러 개로 m²당 단가 하나를 맞히는 다중·단변량 회귀이고, 2026-11-13 스냅샷 한 번으로 학습하는 배치 학습이다.

### 1.2 컴포넌트와 데이터 파이프라인 {#data-pipeline}

책은 모델 출력이 다른 시스템(투자 분석)의 입력이 되는 구조를 먼저 그린다. 데이터 처리 컴포넌트가 줄지어 이어진 것을 **데이터 파이프라인**이라 부른다.

| 특징 | 의미 |
| --- | --- |
| 비동기 실행 | 각 컴포넌트는 데이터를 읽어 처리하고 결과를 다른 저장소에 쓴다. 다음 컴포넌트는 나중에 그 결과를 읽는다 |

## 2. 성능 지표: RMSE와 MAE (2.2.2) {#rmse-mae}

회귀의 대표 지표는 **평균 제곱근 오차**(RMSE)이다. 오차를 제곱해 평균을 낸 뒤 제곱근을 씌우므로 큰 오차에 무게가 실린다.

$$
\mathrm{RMSE}(\mathbf{X}, h) = \sqrt{\frac{1}{m}\sum_{i=1}^{m}\left(h(\mathbf{x}^{(i)}) - y^{(i)}\right)^2}
$$

이상치가 많으면 **평균 절대 오차**(MAE)가 낫다. 오차의 절댓값을 평균하므로 큰 오차 하나에 덜 끌려간다.

$$
\mathrm{MAE}(\mathbf{X}, h) = \frac{1}{m}\sum_{i=1}^{m}\left|h(\mathbf{x}^{(i)}) - y^{(i)}\right|
$$

두 지표는 예측 벡터와 정답 벡터 사이의 거리, 즉 **노름**이다.

| 지표 | 노름 | 다른 이름 | 성질 |
| --- | --- | --- | --- |
| RMSE | \(\ell_2\) | 유클리드 노름 | 지수가 커서 큰 값에 민감하다 |
| MAE | \(\ell_1\) | 맨해튼 노름 | 직각으로만 움직이는 거리. 이상치에 덜 민감하다 |

노름의 지수가 클수록 큰 원소에 치우치고 작은 원소는 무시된다. 이상치가 종 모양 분포의 양 끝처럼 드물면 RMSE가 잘 맞아 기본값으로 많이 쓰인다.

**캡스톤과 연결.** 매물 가격은 650 ~ 216,800만엔으로 꼬리가 매우 길고, 사이트에 10배로 잘못 올라온 가격도 있었다. B 단계 기준선을 MAE와 MAPE(백분율 오차, 책에는 없다)로 잰 이유가 여기에 있다. 단가 수준이 구마다 4배 가까이 다르므로, 비싼 구의 큰 절대 오차가 지표를 지배하지 않게 하려면 백분율 지표를 함께 본다.

## 4. 테스트 세트 만들기 (2.3.7) {#test-set}

### 4.1 데이터 스누핑 편향 {#data-snooping}

데이터를 더 들여다보기 전에 테스트 세트부터 떼어 놓는다. 사람의 뇌는 패턴을 너무 잘 찾아서, 테스트 세트를 본 순간 그 패턴에 맞는 모델을 고르게 된다. 이렇게 고른 모델의 테스트 오차는 낙관적이고, 출시 후에는 기대한 성능이 나오지 않는다. 이를 **데이터 스누핑 편향**이라 한다.

캡스톤 B 단계의 기준선 오차(MAE 3,886만엔)는 학습에 쓴 데이터로 다시 잰 값이라 같은 이유로 낙관적이다. D 단계의 `eda_report` 가 train 분할만 읽는 것도 이 편향을 막기 위해서이다.

### 4.2 시드와 해시 기반 분할 {#hash-split}

무작위로 20%를 떼면 실행할 때마다 다른 테스트 세트가 나온다. 여러 번 돌리면 결국 전체 데이터를 보게 된다.

| 방법 | 같은 데이터로 다시 실행 | 데이터가 갱신되었을 때 |
| --- | --- | --- |
| 첫 실행의 테스트 세트를 저장 | 같다 | 새 샘플이 어디로 갈지 정해지지 않는다 |
| 난수 시드 고정(`random_state=42`) | 같다 | 행이 늘면 분할이 통째로 바뀐다 |
| **식별자의 해시**로 결정 | 같다 | 기존 샘플은 원래 세트에 남고, 새 샘플만 비율대로 나뉜다 |

해시 방식은 식별자의 해시값(예: `crc32`)이 최댓값의 20%보다 작으면 테스트 세트로 보낸다. 식별자는 고유하고 바뀌지 않아야 한다. 주택 데이터에는 ID 열이 없어 행 인덱스를 쓰거나, 몇 년이 지나도 그대로인 위도와 경도를 묶어 ID를 만든다.

```python
from zlib import crc32
import numpy as np

def in_test_set(key, test_ratio=0.2):
    return crc32(str(key).encode()) < test_ratio * 2**32
```

책은 각주에서 위치로 만든 ID의 부작용도 짚는다. 위치 정밀도가 낮으면 여러 구역이 같은 ID를 가져 같은 세트로 몰리고, 이것이 샘플링 편향이 된다.

**캡스톤과 연결.** 캡스톤은 이 부작용을 오히려 의도적으로 쓴다. 같은 초메(丁目)의 매물을 한 세트로 몰아야 처음 보는 동네에 대한 성능을 잴 수 있기 때문이다. 다만 `GroupShuffleSplit(random_state=42)` 는 시드 방식이라, `--snapshot` 으로 새로 수집한 데이터를 넣으면 초메 배정이 통째로 바뀐다. `chome_key` 의 해시로 나누면 기존 초메는 원래 세트에 남고, 새로 생긴 초메만 비율대로 나뉜다.

### 4.3 계층적 샘플링 {#stratified}

데이터가 충분히 크지 않으면 순수 무작위 분할에 샘플링 편향이 생긴다. 전체를 **계층**이라는 동질 그룹으로 나누고, 계층마다 비율대로 뽑는 것을 **계층적 샘플링**이라 한다. 계층은 너무 잘게 나누지 않고, 각 계층에 샘플이 충분해야 한다.

예제는 가격 예측에 중요한 중간 소득을 `pd.cut` 으로 5개 구간(`income_cat`)으로 나눠 계층으로 쓴다.

```python
from sklearn.model_selection import StratifiedShuffleSplit, train_test_split

housing["income_cat"] = pd.cut(housing["median_income"],
                               bins=[0., 1.5, 3.0, 4.5, 6., np.inf], labels=[1, 2, 3, 4, 5])

# 분할 하나면 stratify 인자로 충분하다
strat_train, strat_test = train_test_split(
    housing, test_size=0.2, stratify=housing["income_cat"], random_state=42)
```

`StratifiedShuffleSplit(n_splits=10)` 은 서로 다른 계층 분할 10개를 만든다. 결과를 비교하면 차이가 분명하다.

| 소득 카테고리 | 전체 % | 계층 샘플링 오차 % | 무작위 샘플링 오차 % |
| --- | ---: | ---: | ---: |
| 1 | 3.98 | 0.36 | 6.45 |
| 2 | 31.88 | -0.02 | -3.59 |
| 3 | 35.06 | -0.01 | -1.53 |
| 4 | 17.63 | 0.03 | 4.42 |
| 5 | 11.44 | -0.08 | 5.63 |

`income_cat` 은 분할에만 쓰고 바로 지운다.

**캡스톤과 연결.** 캡스톤에서 계층에 해당하는 것은 구(区)이다. QA 검사 "23구가 모든 분할에 존재" 는 계층이 빠지지 않았는지만 보는 약한 형태의 확인이다. 그룹(초메)을 지키면서 구 비율도 맞추려면 사이킷런의 `StratifiedGroupKFold` 를 쓴다(책 밖의 클래스). 행 비율이 73.8 / 16.1 / 10.1 로 정확히 떨어지지 않는 것은 그룹 단위 분할의 대가이다.

## 5. 탐색과 시각화 (2.4) {#explore}

탐색은 **훈련 세트만** 대상으로 한다. 훈련 세트가 아주 크면 탐색용 표본을 따로 뽑는다. 여러 변환을 시험할 것이므로 원본은 복사해 둔다.

### 5.1 지리적 산점도 {#geo-scatter}

위도와 경도가 있으면 산점도로 지도를 그린다. 점이 겹치면 밀도가 안 보이므로 `alpha=0.2` 를 준다. 여기에 원 크기(`s`)로 인구를, 색(`c`)으로 가격을 얹는다.

```python
housing.plot(kind="scatter", x="longitude", y="latitude", grid=True, alpha=0.2,
             s=housing["population"] / 100, c="median_house_value", cmap="jet",
             colorbar=True, figsize=(10, 7))
```

가격은 바다와의 거리, 인구 밀도와 관련이 크다. 군집 알고리즘으로 주요 군집을 찾고 군집 중심까지의 거리를 특성으로 넣을 수 있다. 해안 근접성도 쓸 만하지만, 북부 해안은 가격이 높지 않아 단순한 규칙으로는 안 된다.

**캡스톤과 연결.** 지오코딩으로 붙인 `lat`, `lon` 에 단가를 색으로 얹으면 같은 그림이 나온다. 구(区) 경계 안에서도 단가가 고르지 않다는 것(미타(三田) 391, 코난(港南) 195)을 지도로 확인할 수 있다.

### 5.2 상관관계 {#correlation}

`corr()` 는 수치 특성 사이의 **표준 상관계수**(피어슨 r)를 계산한다. -1 ~ 1 범위이고, 0에 가까우면 **선형** 관계가 없다는 뜻이다. 비선형 관계(예: x가 0에 가까울 때만 y가 커지는 경우)는 잡지 못하고, 기울기 크기와도 무관하다.

중간 주택 가격과 상관이 가장 높은 것은 중간 소득(0.688)이다. 둘의 산점도를 크게 그리면 두 가지가 더 보인다.

- 상관이 강해 점들이 뚜렷하게 위로 향한다.
- 50만 달러의 상한이 수평선으로 보이고, 45만, 35만, 28만 달러 근처에도 수평선이 있다. 모델이 이 이상한 형태를 배우지 않도록 해당 구역을 지울 수 있다.

`pandas.plotting.scatter_matrix` 는 특성 쌍마다 산점도를, 대각선에는 히스토그램을 그린다.

**캡스톤과 연결.** 가격 10배 오류 2건은 상관이 아니라 구(区) 중앙 단가 대비 배수로 찾았지만, 생각의 방향은 같다. 단가와 면적의 산점도에서 무리에서 떨어진 점, 특정 가격대에 몰린 줄(중개사가 쓰는 딱 떨어지는 호가)을 먼저 본다.

### 5.3 특성 조합 {#feature-combo}

그 자체로는 쓸모가 적은 특성을 조합하면 유용해진다. 구역의 전체 방 수보다 **가구당 방 수**, 전체 침실 수보다 **방 대비 침실 비율**이 의미 있다.

| 특성 | 가격과의 상관계수 |
| --- | ---: |
| `median_income` | 0.688 |
| `rooms_per_house` (방 수 / 가구 수) | 0.144 |
| `total_rooms` | 0.137 |
| `bedrooms_ratio` (침실 수 / 방 수) | **-0.256** |

`bedrooms_ratio` 는 원래 특성보다 상관이 훨씬 강하다. 침실 비율이 낮은 집일수록 비싸다. 다만 기존 특성의 단순한 가중합으로 새 특성을 만들면 **공선성** 때문에 선형 회귀 같은 모델에서 문제가 생긴다.

**캡스톤과 연결.** 타깃 자체가 특성 조합이다. 가격을 면적으로 나눈 m²당 단가로 바꾸면 위치가 설명하는 부분이 커진다. 같은 발상으로 `所在階 / 総階数`(건물 안에서의 상대 높이) 같은 비율 특성을 8장에서 후보로 둔다.

## 6. 데이터 정제와 범주형 특성 (2.5.1 ~ 2.5.2) {#clean-categorical}

데이터 준비는 손으로 하지 않고 함수로 만든다. 새 데이터에도 같은 변환을 반복할 수 있고, 서빙 시스템에서도 같은 함수로 입력을 변환할 수 있기 때문이다. 시작할 때 예측 변수와 레이블을 분리한다.

### 6.1 결측치 처리 {#imputer}

`total_bedrooms` 의 빈 값을 처리하는 방법은 세 가지이다.

| 방법 | pandas | 비고 |
| --- | --- | --- |
| 해당 구역 제거 | `dropna(subset=[...])` | 행이 줄어든다 |
| 특성 전체 삭제 | `drop(columns=[...])` | 정보가 사라진다 |
| 어떤 값으로 채우기(**대체**) | `fillna(median)` | 데이터를 가장 많이 남긴다 |

사이킷런의 `SimpleImputer(strategy="median")` 는 훈련 세트에서 중간값을 학습해 `statistics_` 에 저장한다. 같은 값으로 검증·테스트 세트와 서빙 입력까지 채울 수 있어서 `fillna` 보다 낫다. 지금은 `total_bedrooms` 만 비어 있지만, 서빙 때 어느 열이 빌지 모르므로 **모든 수치 특성에** 적용한다.

```python
from sklearn.impute import SimpleImputer

imputer = SimpleImputer(strategy="median")
imputer.fit(housing.select_dtypes(include=[np.number]))
```

전략은 `mean`, `most_frequent`, `constant` 도 있고, 뒤의 둘은 수치가 아닌 데이터도 받는다. 더 강력한 대체 방법으로 k-최근접 이웃 평균을 쓰는 `KNNImputer`, 특성마다 회귀 모델로 빈 값을 예측하고 반복해 다듬는 `IterativeImputer` 가 있다.

**캡스톤과 연결.** 캡스톤은 총 층수, 구조, 방향(総階数·構造·向き)이 빈 행을 지우지 않고 결측 그대로 둔다. 서빙 때 선택 입력이라 비어서 들어오기 때문이다. 8장에서 결측을 바로 받는 트리 계열을 쓰지 않는다면, 대체기를 파이프라인 안에 넣어 train에서 학습한 값으로 서빙 입력까지 채운다.

### 6.2 사이킷런의 설계 원칙 {#sklearn-design}

사이킷런 API는 일관된 인터페이스 세 가지로 이뤄진다.

| 역할 | 메서드 | 예 |
| --- | --- | --- |
| **추정기** | `fit()` 으로 데이터에서 파라미터를 추정한다. 하이퍼파라미터는 생성자 인자로 받는다 | `SimpleImputer`, `LinearRegression` |
| **변환기** | `transform()` 으로 학습한 값을 써서 데이터를 바꾼다. `fit_transform()` 이 둘을 한 번에 한다 | `SimpleImputer`, `StandardScaler` |
| **예측기** | `predict()` 로 예측하고 `score()` 로 품질을 잰다 | `LinearRegression` |

이 밖에 하이퍼파라미터와 학습된 파라미터(이름 끝에 `_`)를 그대로 들여다볼 수 있고, 데이터는 넘파이 배열이나 희소 행렬로 주고받으며, 기존 부품을 엮어 `Pipeline` 으로 조합할 수 있다. 출력은 기본적으로 넘파이 배열이라, 데이터프레임이 필요하면 `get_feature_names_out()` 으로 열 이름을 되살린다.

### 6.3 범주형 특성 인코딩 {#categorical}

`ocean_proximity` 는 정해진 값만 갖는 범주형 특성이다. 모델은 숫자를 받으므로 변환해야 한다.

| 인코더 | 출력 | 문제나 장점 |
| --- | --- | --- |
| `OrdinalEncoder` | 카테고리마다 정수 하나 | 가까운 숫자를 비슷하다고 본다. 순서가 있는 카테고리에만 맞다 |
| `OneHotEncoder` | 카테고리마다 이진 열(**원-핫**, 더미 특성) | 기본 출력이 희소 행렬이다. `sparse_output=False` 로 밀집 배열을 받는다 |
| `pd.get_dummies()` | 이진 열 | 들어온 데이터에 있는 카테고리만 열로 만든다. 학습 때의 열 구성을 기억하지 못한다 |

`OneHotEncoder` 는 학습한 카테고리를 기억하므로 훈련과 서빙에서 열 구성이 같다. 모르는 카테고리가 들어오면 예외를 내고, `handle_unknown="ignore"` 이면 모든 열을 0으로 둔다. 카테고리 수가 아주 많으면 입력 특성이 너무 많아지므로, 관련된 숫자 특성으로 바꾸거나(국가 코드 대신 인구와 1인당 GDP) 학습 가능한 **임베딩**을 쓴다.

**캡스톤과 연결.** 범주형 열마다 처리가 다르다.

| 열 | 카테고리 수 | 처리 방향 |
| --- | --- | --- |
| 구조(`構造`) | 정리 후 4종(RC, SRC, S, 기타) | 원-핫 |
| 방향(`向き`) | 8방위 | 원-핫, 또는 각도를 sin, cos 두 숫자로 |
| 방 구조(`間取り`) | 1R ~ 5LDK 등 | 방 수(숫자)와 유형(L, D, K)으로 나눈다 |
| 가장 가까운 역(`最寄駅`) | 매우 많다 | 원-핫 대신 역 좌표나 역별 통계 같은 숫자 특성으로 바꾼다. 서빙 때 처음 보는 역은 `handle_unknown` 으로 막는다 |

## 7. 꼬리가 긴 특성과 타깃 변환 (2.5.3 후반) {#transforms}

스케일링(min-max, 표준화)은 [앞 글](../hands-on-ml-02-end-to-end-project/)에서 다뤘다. 여기서는 그 뒤에 나오는 변환만 정리한다.

| 변환 | 언제 | 예 |
| --- | --- | --- |
| 로그, 제곱근 | 오른쪽 꼬리가 두꺼울 때. 거듭제곱 분포에는 로그 | `population` 을 로그로 바꾸면 종 모양에 가까워진다 |
| **버킷타이징** | 분포를 비슷한 크기의 구간으로 잘라 구간 번호로 바꾼다. 멀티모달 분포면 번호를 카테고리로 보고 원-핫 | `housing_median_age` |
| **RBF 유사도** | 특정 값(모드) 근처라는 사실 자체가 의미 있을 때 | 연식 35년과의 가우스 RBF, \(\exp(-\gamma(x-35)^2)\) |

\(\gamma\) 가 클수록 35에서 멀어질 때 유사도가 빨리 0으로 떨어진다. `sklearn.metrics.pairwise.rbf_kernel` 로 계산한다.

타깃도 꼬리가 길면 로그로 바꿀 수 있다. 이 경우 모델은 가격이 아니라 로그 가격을 예측하므로, 예측에 역변환(지수 함수)을 적용해야 한다. `TransformedTargetRegressor` 는 학습 때 레이블을 변환하고 예측 때 `inverse_transform()` 을 자동으로 적용한다.

```python
from sklearn.compose import TransformedTargetRegressor
from sklearn.preprocessing import FunctionTransformer

model = TransformedTargetRegressor(
    regressor=LinearRegression(),
    transformer=FunctionTransformer(np.log, inverse_func=np.exp))
```

**캡스톤과 연결.** 캡스톤은 타깃을 가격 대신 m²당 단가로 바꿨고, 출력에서 다시 면적을 곱해 가격으로 돌린다. 단가도 18.5 ~ 1,487.2만엔/m² 로 꼬리가 길어, 로그 단가를 학습하는 것이 8장의 후보가 된다. 준공 연도(築年)처럼 특정 시기(예: 신내진 기준 1981년 전후)에 의미가 몰린 특성은 버킷타이징이나 RBF 유사도의 대상이다.

## 8. 사용자 정의 변환기와 파이프라인 (2.5.4 ~ 2.5.5) {#custom-transformer}

### 8.1 FunctionTransformer

학습할 것이 없는 변환은 함수 하나로 변환기를 만든다.

```python
log_transformer = FunctionTransformer(np.log, inverse_func=np.exp)

# 추가 인자는 kw_args 로. 샌프란시스코와의 지리적 유사도
sf_simil = FunctionTransformer(rbf_kernel, kw_args=dict(Y=[[37.7749, -122.41]], gamma=0.1))
sf_simil.transform(housing[["latitude", "longitude"]])

# 두 열의 비율
ratio = FunctionTransformer(lambda X: X[:, [0]] / X[:, [1]])
```

### 8.2 학습하는 변환기 클래스

`fit()` 에서 무언가 배워야 한다면 클래스를 만든다. 사이킷런은 상속이 아니라 덕 타이핑에 의존하므로 `fit()`(항상 `self` 반환), `transform()` 만 있으면 된다.

| 상속 | 얻는 것 |
| --- | --- |
| `TransformerMixin` | `fit_transform()` 이 자동으로 생긴다 |
| `BaseEstimator` | `get_params()`, `set_params()` 가 생겨 하이퍼파라미터 튜닝이 된다. 생성자에 `*args`, `**kwargs` 를 쓰지 않아야 한다 |

지켜야 할 규칙은 이렇다. `fit()` 은 `y=None` 인자를 받아야 파이프라인에 들어가고, `n_features_in_` 을 저장해 `transform()` 에서 특성 수가 같은지 확인한다. 실제 제품 코드라면 `check_array`, `check_is_fitted` 로 입력을 검증하고, `get_feature_names_out()` 과 `inverse_transform()` 도 제공한다.

예제의 `ClusterSimilarity` 는 `fit()` 에서 `KMeans` 로 위도·경도의 군집 중심 10개를 찾고, `transform()` 에서 각 구역과 군집 중심들 사이의 가우스 RBF 유사도를 낸다.

```python
from sklearn.base import BaseEstimator, TransformerMixin
from sklearn.cluster import KMeans

class ClusterSimilarity(BaseEstimator, TransformerMixin):
    def __init__(self, n_clusters=10, gamma=1.0, random_state=None):
        self.n_clusters, self.gamma, self.random_state = n_clusters, gamma, random_state

    def fit(self, X, y=None, sample_weight=None):
        self.kmeans_ = KMeans(self.n_clusters, random_state=self.random_state)
        self.kmeans_.fit(X, sample_weight=sample_weight)
        return self

    def transform(self, X):
        return rbf_kernel(X, self.kmeans_.cluster_centers_, gamma=self.gamma)

    def get_feature_names_out(self, names=None):
        return [f"군집 {i} 유사도" for i in range(self.n_clusters)]
```

`sample_weight` 로 중간 가격을 넘기면 비싼 지역 쪽으로 치우친 군집을 만들 수 있다. k-평균은 무작위성에 의존하므로 `random_state` 를 고정해야 결과가 재현된다. `sklearn.utils.estimator_checks.check_estimator()` 로 사이킷런 API를 지키는지 검사할 수 있다.

**캡스톤과 연결.** 지오코딩이 붙인 `lat`, `lon` 에 그대로 쓸 수 있는 변환기이다. 군집 수는 하이퍼파라미터라 9절의 그리드 서치로 고른다. 도쿄라면 도심(지요다·미나토·주오) 쪽 중심과의 유사도가 단가를 크게 설명할 것으로 기대하고, 이는 8장에서 확인한다.

### 8.3 Pipeline과 ColumnTransformer {#sklearn-pipeline}

변환은 순서대로 실행되어야 한다. `Pipeline` 은 이름과 추정기 쌍의 리스트를 받고, 마지막을 뺀 단계는 모두 변환기여야 한다. `fit()` 을 부르면 각 단계의 `fit_transform()` 출력을 다음 단계 입력으로 넘기고, 마지막 단계는 `fit()` 만 한다.

```python
from sklearn.pipeline import make_pipeline
from sklearn.compose import ColumnTransformer, make_column_selector

num_pipeline = make_pipeline(SimpleImputer(strategy="median"), StandardScaler())
cat_pipeline = make_pipeline(SimpleImputer(strategy="most_frequent"),
                             OneHotEncoder(handle_unknown="ignore"))

preprocessing = ColumnTransformer([
    ("num", num_pipeline, make_column_selector(dtype_include=np.number)),
    ("cat", cat_pipeline, make_column_selector(dtype_include=object)),
])
```

| 기능 | 쓰는 법 |
| --- | --- |
| 이름 자동 생성 | `make_pipeline` 은 클래스 이름을 소문자로 바꿔 이름을 붙인다 |
| 인덱싱 | `pipeline[1]`, `pipeline[:-1]`, `pipeline["simpleimputer"]` |
| 열별 다른 변환 | `ColumnTransformer` 에 (이름, 변환기, 열 목록) 튜플을 준다 |
| 나머지 열 | 기본은 `remainder="drop"`. `"passthrough"` 나 변환기를 줄 수 있다 |
| 시각화 | `sklearn.set_config(display="diagram")` |

책의 최종 전처리기는 비율 특성 3개(대체, 비율, 표준화), 로그 특성 5개, 군집 유사도 10개, 원-핫 5개, 나머지 1개로 **24개 특성**을 낸다.

**캡스톤과 연결.** 이름은 같지만 층위가 다르다.

| | 사이킷런 `Pipeline` | KFP 파이프라인 |
| --- | --- | --- |
| 단위 | 파이썬 객체 안의 변환 단계 | Pod 하나로 뜨는 컴포넌트 |
| 데이터 전달 | 메모리 안의 배열 | 아티팩트 경로나 고정 경로 |
| 저장 | 학습된 파이프라인 전체를 `joblib` 파일 하나로 | 단계마다 버킷에 남는 파일 |
| 서빙 | 같은 객체로 입력을 변환하고 예측 | 서빙에는 쓰지 않는다 |

D 단계의 주소 정규화와 지오코딩은 학습 데이터 준비이지만, 서빙 때 사용자가 넣은 주소에도 똑같이 적용되어야 한다. 정규화 함수를 `FunctionTransformer` 로 감싸 학습 파이프라인 맨 앞에 두면, 모델 파일 하나에 같은 코드가 들어가 학습과 서빙의 변환이 어긋나지 않는다.

## 9. 모델 선택, 교차 검증, 튜닝 (2.6 ~ 2.7) {#model-selection}

### 9.1 훈련 세트에서 먼저 재 보기

전처리 파이프라인 뒤에 모델을 붙이면 학습 코드는 두 줄이다.

| 모델 | 훈련 세트 RMSE | 판단 |
| --- | ---: | --- |
| `LinearRegression` | 68,973 | 대부분 구역 가격이 12만 ~ 26.5만 달러인데 오차가 7만 달러 가깝다. **과소적합** |
| `DecisionTreeRegressor` | 0 | 오차가 없다. 심하게 **과대적합**했을 가능성이 크다 |

과소적합이면 더 강력한 모델, 더 좋은 특성, 규제 완화를 시도한다. 과대적합인지 확인하려면 테스트 세트를 건드리지 않고 훈련 세트 안에서 검증해야 한다.

### 9.2 k-폴드 교차 검증 {#cross-validation}

훈련 세트를 겹치지 않는 폴드 k개로 나누고, 한 폴드로 평가하고 나머지로 학습하기를 k번 반복한다. 점수 k개가 나오므로 성능의 추정값과 그 추정의 정확도(표준 편차)를 함께 얻는다. 대신 모델을 k번 학습하므로 비용이 크다.

```python
from sklearn.model_selection import cross_val_score

rmses = -cross_val_score(tree_reg, housing, housing_labels,
                         scoring="neg_root_mean_squared_error", cv=10)
```

사이킷런의 교차 검증은 클수록 좋은 효용 함수를 기대하므로, RMSE는 음수로 받아 부호를 뒤집는다.

| 모델 | 교차 검증 RMSE 평균 | 표준 편차 | 훈련 RMSE |
| --- | ---: | ---: | ---: |
| 선형 회귀 | 70,003 | 4,182 | 68,973 |
| 결정 트리 | 66,574 | 1,103 | 0 |
| 랜덤 포레스트 | 47,038 | 1,021 | 17,551 |

랜덤 포레스트는 여러 결정 트리의 예측을 평균하는 **앙상블**이다. 훨씬 낫지만 훈련 RMSE와의 차이가 커서 여전히 과대적합되어 있다. 이 단계에서는 한 모델을 깊이 튜닝하기보다 여러 종류의 모델로 가능성 있는 후보 2 ~ 5개를 고른다.

**캡스톤과 연결.** 캡스톤의 비교 기준은 B 단계의 구별 중앙 단가 기준선이다. 8장 교차 검증에서 폴드를 행 단위로 나누면 C 단계에서 본 98.3% 누수가 그대로 생기므로, 초메(丁目)를 그룹으로 `GroupKFold` 를 쓴다(책 밖의 클래스).

### 9.3 그리드 서치와 랜덤 서치 {#grid-search}

`GridSearchCV` 는 지정한 하이퍼파라미터 조합을 모두 교차 검증으로 평가한다. 파이프라인 안의 하이퍼파라미터는 이중 밑줄로 경로를 적는다. `preprocessing__geo__n_clusters` 는 `preprocessing` 단계 안의 `geo` 변환기의 `n_clusters` 이다.

| 항목 | 값 |
| --- | --- |
| 탐색 공간 | 3 × 3 + 2 × 3 = 15개 조합 |
| 학습 횟수 | 3-폴드라 15 × 3 = 45번 |
| 최적 조합 | `n_clusters=15`, `max_features=6` |
| 최적 RMSE | 43,590 (기본값 47,038에서 개선) |

최적값이 탐색 범위의 끝(15)에 걸렸다면 범위를 넓혀 다시 탐색한다. `refit=True`(기본값)이면 최적 조합으로 전체 훈련 세트에 다시 학습한 모델이 `best_estimator_` 에 남는다. 전처리 변환기가 무거우면 파이프라인의 `memory` 인자로 학습된 변환기를 캐싱한다.

탐색 공간이 크면 `RandomizedSearchCV` 를 쓴다. 정해진 횟수만큼 무작위 조합을 평가하므로 연속값 하이퍼파라미터의 값을 훨씬 다양하게 시도하고, 쓸모없는 하이퍼파라미터를 추가해도 시간이 늘지 않는다. `HalvingRandomSearchCV` 와 `HalvingGridSearchCV` 는 첫 라운드에 후보를 적은 자원으로 평가하고, 살아남은 후보에만 자원을 늘려 준다.

### 9.4 최상의 모델 분석 {#error-analysis}

랜덤 포레스트의 `feature_importances_` 로 특성의 상대 중요도를 본다. 예제에서는 로그 중간 소득, `INLAND` 카테고리, 침실 비율 순이고, `ocean_proximity` 의 다른 카테고리는 거의 쓰이지 않는다. 덜 중요한 특성은 지우거나 `SelectFromModel` 로 자동으로 고른다.

특정 오차가 나왔다면 원인을 찾아 특성을 더하거나 빼고 이상치를 정리한다. 평균 성능만 보지 말고 시골과 도시, 부유한 곳과 가난한 곳처럼 **서브셋별로 검증 세트를 나눠** 성능을 확인한다. 어떤 범주에서 제대로 동작하지 않으면 그 범주에는 모델을 쓰지 않거나 고칠 때까지 배포하지 않는다.

**캡스톤과 연결.** B 단계의 `SlicedClassificationMetrics`(구별 슬라이스 23개)와 오차 분포 `HTML` 이 이 분석의 틀이다. 8장에서는 구별, 준공 연대별, `geo_level`(초메 매칭인지 동 매칭인지)별로 오차를 나눠 본다.

### 9.5 테스트 세트로 평가 {#test-evaluation}

마지막에 한 번만 테스트 세트로 평가한다. 예제의 최종 RMSE는 41,445이다. 점 추정만으로는 출시 판단이 어려우므로 신뢰 구간을 함께 낸다.

```python
from scipy import stats

squared_errors = (final_predictions - y_test) ** 2
boot = stats.bootstrap([squared_errors], lambda e: np.sqrt(np.mean(e)),
                       confidence_level=0.95, random_state=42)
boot.confidence_interval   # 39,521 ~ 43,702
```

하이퍼파라미터를 많이 튜닝했다면 테스트 성능은 교차 검증보다 조금 낮은 것이 보통이다. 이때 테스트 점수를 올리려고 다시 튜닝하면 안 된다. 그 개선은 새 데이터로 일반화되지 않는다.

**캡스톤과 연결.** test 분할(2,435행, 244 초메)은 8장의 마지막에 한 번만 연다. 출력이 80% 구간이므로, 점 오차와 함께 실제 단가가 구간 안에 드는 비율(목표 80%)도 test에서 잰다.

## 10. 론칭, 모니터링, 유지 보수 (2.7.5 후반 ~ 2.8) {#launch}

### 10.1 재현 가능하게 남기기 {#reproducibility}

출시 전에는 무엇을 배웠고, 무엇이 됐고 안 됐으며, 어떤 가정을 했고, 한계가 무엇인지 정리한다. 결과는 재현 가능해야 한다.

- 코드, 설명, 결과가 든 노트북과 README
- 정확한 라이브러리 버전이 적힌 `requirements.txt` 나 `environment.yml`, 또는 Docker 이미지
- 난수 시드를 고정하고, 결과를 흔드는 요소를 모두 제거

**캡스톤과 연결.** E 단계에서 이미지 태그를 고정하자 pandas 3.1.1, pyarrow 26.0.1 로 D 단계와 바이트까지 같은 Parquet이 나왔다. 반대로 경량 컴포넌트는 Pod가 뜰 때마다 최신 버전을 받아 시간이 지나면 결과가 달라질 수 있다.

### 10.2 모델 저장과 서빙 {#model-serving}

`joblib.dump(final_model, "my_california_housing_model.pkl")` 로 전처리까지 든 파이프라인 전체를 저장한다. 비교할 수 있도록 실험한 모델은 모두 저장한다.

불러올 때는 모델이 쓰는 **사용자 정의 클래스와 함수를 먼저 import** 해야 한다(`column_ratio`, `ClusterSimilarity` 등). 즉 그 코드도 제품 환경으로 함께 가야 한다.

서빙 방식은 두 가지를 든다.

| 방식 | 구조 |
| --- | --- |
| 웹 애플리케이션 안에서 직접 | 서버가 시작될 때 모델을 한 번 로드하고 요청마다 `predict()` |
| 별도 웹 서비스 | 애플리케이션이 REST API로 질의한다. 모델 버전을 따로 올리고, 부하 분산으로 확장하며, 다른 언어로 쓴 앱도 붙는다 |

클라우드에서는 모델을 GCS에 올리고 Vertex AI에 버전을 만들면 부하 분산과 자동 확장을 처리하는 서비스가 생긴다.

**캡스톤과 연결.** E 단계에서 주소 정규화를 `address.py` 로 빼 두 컴포넌트가 import 하게 한 것이 이 규칙과 같다. 서빙 이미지에도 같은 모듈이 들어가야 저장한 모델이 로드된다. 별도 웹 서비스 방식은 [BentoML 글](../../mlpe/mlpe-06-1-bentoml-yatai/)의 구조이다.

### 10.3 모니터링과 재학습 {#monitoring}

배포가 끝이 아니다. 컴포넌트 고장처럼 성능이 갑자기 떨어지기도 하지만, 세상이 바뀌어 천천히 떨어지는 **모델 드리프트**가 더 흔하다.

| 감시 대상 | 방법 |
| --- | --- |
| 모델 성능 | 하위 지표(추천 상품 판매량 등)로 추정하거나, 예측 표본을 사람이 평가한다 |
| 입력 데이터 품질 | 누락이 늘어나는 특성, 훈련 세트와 멀어진 평균·표준 편차, 처음 보는 카테고리를 경보로 잡는다 |
| 자동화 | 정기 수집과 레이블링, 재학습과 튜닝 스크립트, 새 모델과 이전 모델을 테스트 서브셋별로 비교해 나빠지지 않을 때만 배포 |
| 백업 | 모든 모델과 모든 버전의 데이터셋을 남겨 빠르게 롤백한다 |

책은 이 전체를 **MLOps**라 부르고, 모델을 만드는 것보다 이쪽 일이 더 많은 경우가 흔하다고 정리한다.

**캡스톤과 연결.** 입력 품질 감시는 [Evidently 글](../../mlpe/mlpe-06-2-evidently-drift/)의 드리프트 검사로 할 수 있다. 데이터셋 백업은 날짜가 든 경로(`suumo/raw/2026-11-13/`, `suumo/prepared/2026-11-13/`)로 스냅샷을 쌓는 방식으로 이미 지키고 있다. 처음 보는 역이나 구조 카테고리는 서빙 입력에서 바로 세어 경보로 삼는다.
